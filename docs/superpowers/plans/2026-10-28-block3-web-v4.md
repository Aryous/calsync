# Block ③ — the web UI from concept v4 (phase B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v1 "ticket wallet" front end with the approved concept v4 — a sync map that is also the configuration surface, a six-view calendar with per-target delivery state, an event detail comparing the Google original with the iCloud copy, an activity timeline, settings, an account wizard and the blocked-delete flow — wired to the phase A JSON API, phone-first for viewing and desktop-first for configuring.

**Architecture:** Same delivery as today: static ES modules served by the daemon (`/static/...`, Preact + htm vendored, no build step), one page at `/` behind the existing pairing guard. The UI reads `GET /api/*` and changes things only through `POST /api/ops/<name>` (source `ui`). Hash routes select the inspector (`#/rule/<name>`, `#/calendar/<account>/<id>`, `#/account/<name>`, `#/settings`, `#/new`, `#/event/<id>`, `#/blocked/<rule>`, `#/activity`). Browser tests drive a real in-process daemon (fake Google/iCloud adapters from `tests/fakes`, synthetic config and state) over loopback HTTP.

**Tech Stack:** Preact + htm (vendored), vanilla CSS with tokens, Python Playwright (Chromium + WebKit) for browser tests, pytest.

**Inputs (read before every task):**
- The approved concept: `.impeccable/mocks/canvas/index.html` and its brief `.impeccable/mocks/canvas/BRIEF.md` (open the HTML in a browser; its structure, tokens, copy and interactions are the visual source of truth).
- Feasibility and decisions: `docs/superpowers/specs/2026-10-27-concept-v4-feasibility.md` (§3 rows marked for the GUI, §4 "only humans", §5 wording, §6 decisions).
- The phase A API: `docs/agent-cli.md`, `src/calsync/api.py`, `src/calsync/views.py`, `src/calsync/events_view.py`, `src/calsync/ops.py` (op names and args).
- `PRODUCT.md`, `AGENTS.md`, the v2 spec §5 (`docs/superpowers/specs/2026-10-24-calsync-v2-product-design.md`).

## Global Constraints

- **Stack (D13):** Preact + htm from `/static/vendor/htm-preact-standalone.mjs`; ES modules under `src/calsync/web/static/`; no build step, no CDN, nothing loaded from another origin.
- **CSP (`web/app.py`):** `default-src 'self'` — no inline `<script>`, no inline event handlers, no `style="..."` attributes in markup and no `setAttribute("style", …)`. Dynamic geometry (wire paths, event block positions) goes through SVG attributes or Preact style *objects* (CSSOM), never style strings. Keep the CSP as it is.
- **Plain HTTP (D8):** nothing that needs a secure context. `navigator.clipboard` is unavailable over HTTP: copy buttons select the text and fall back to `document.execCommand("copy")`, then say "已选中，请手动复制" if that fails.
- **D10 — no secrets in the browser:** no password, token or app-specific password input anywhere. Every step that needs a person shows the runnable command from the op's `needs_human` (with a copy button) and polls until the state changes.
- **The UI never edits events in this phase** (phase C adds it). It never shows the account write-permission toggle.
- **Language:** Chinese by default, English available (`i18n.js`, English text as the key, as today); every visible string goes through `t()`.
- **Layout (D6, PRODUCT.md):** phone ≤ 760 px (or touch ≤ 1024 px): the canvas stays horizontal (columns `1fr 64px 1fr`), the inspector is a bottom sheet (max 88 vh), the calendar hides week and 2-week views; desktop: the inspector is a right panel and the page shifts left so the map stays visible (concept's `.wrap` rule). Tap targets ≥ 44 px, inputs 16 px, safe-area insets, no horizontal scroll at 360 px.
- **Theme:** light and dark tokens exactly as in the concept (`--bg #F8FAFC` … dark set), applied before first paint by `theme.js`; `prefers-reduced-motion` stops the wire comets and the hub breathing.
- **Visual principles (user, 2026-10-26):** relationships before results (no metric cards as the hero); spatial composition (sources left, hub, targets right); quiet creativity (low saturation, thin lines, large whitespace, slow motion; no glow, no 3D, no neon). Font: Instrument Sans (self-hosted, OFL licence file vendored) for Latin and numerals, system PingFang SC for Chinese.
- **Naming rule (user, 2026-10-27):** a calendar name is never shown without its service icon and account (`[Google icon] 家庭日程 · 个人 Google`) — map tooltips, inspectors, legend, layer toggles, list view, activity, new-line picker, event detail.
- **Wording (feasibility §5):** "已送达 iCloud" (not "已送达"); "在 iPhone 上被改了，已改回" (never "有人"); an auth failure lists the common reasons (password changed, access revoked, the Google app is in "testing" status — renew every 7 days) and the reconnect command; deleting a line with its copies explains that the copies are deleted first (and may need approval if there are many), then the line disappears.
- **Every number is evidence:** a count can be tapped to see the items behind it.
- **Privacy:** titles may be shown; nothing is logged to the browser console except errors by kind.
- **Tests:** synthetic data only; the sealed test environment (no real config, keyring, network or launchctl) applies; browser tests run only against `127.0.0.1`. Python: `uv run pytest -q`, `uv run ruff check .`, `uv run ruff format --check src tests`, `uv run pyright` clean after every task. Browser tests: `uv run pytest -q -m browser` (Chromium + WebKit) clean after every task that touches the UI.

**Files:** `map.js`, `app.js`, `styles.css`, `i18n.js`, `tests/browser/test_map.py`.

- Data: `GET /api/status` (`accounts[]` with `calendars[]` — id, name, role, series, rules, synced; `rules[]` with source/target/health; `attention[]`; `summary`; `daemon`).
- Layout from the concept: source accounts (service icon + name + "N 个日历在同步") with calendar pills (colour dot by source calendar, series count; unsynced calendars dashed "未同步"); the hub (dark tile with internal traces, "calsync · N 条线路"); target accounts with calendar pills ("N 个来源"); "连接 Google 账号" / "连接 iCloud 账号" links (open the wizard, Task 4).

- Focus: hovering/selecting a rule or calendar dims the rest.
- Status sentence under the map (concept: "四条线路都在正常工作" + "1 分钟前同步 · 今天送达了 12 处改动 · 下次检查 10:43"), and attention cards for `attention[]` (blocked → opens `#/blocked/<rule>`; auth → shows the reasons and the command with copy; failing → opens the rule).

### Task 3: Rule, calendar and new-line inspectors

**Files:** `inspector.js`, `forms/rule.js`, `forms/calendar.js`, `forms/newline.js`, `styles.css`, `i18n.js`, `tests/browser/test_rules.py`.

- Inspector container: right panel on desktop (page shifts left), bottom sheet on phone, focus moves into it, Esc / close button / back navigation close it, the selected wire highlights.
- **Rule inspector (`#/rule/<name>`):** route chip (service icon · account · calendar → …), state line, and the settings of the concept — 同步范围 (全部 / 只同步一段时间 with past/future days), 提醒 (跟 Google 一样 / 统一设置 with offset pills + add / 不要提醒), 显示内容 (完整 / 只显示忙碌), 参与人 (不复制 / 写进备注), 会议链接 (复制 / 不复制), 目标端被改时 (改回 — explanation), 防误删 (max count / max ratio with validation), 暂停/恢复, 立即同步这一条, 删除这条线路 (two choices: keep the copies / delete the copies too — the second explains retire + possible approval). Every change: `op("rule.set", …)` and a quiet "已保存到 config.toml" indicator; a 422 shows the problem next to the field and reverts the control; a conflict (`ConfigConflict`) reloads the inspector with a notice.
- **Calendar inspector (`#/calendar/<account>/<id>`):** its lines (to/from), "从这个日历新建线路" / "同步到这个日历", for a target: the note that calsync only manages its own copies.
- **New line (`#/new`, prefilled from a calendar):** pick source (grouped by account, with service icon) and target; combinations already synced are disabled; "在 iCloud 里新建一个日历" sets `create_target`; then **预演** via `op("rule.preview", …)` showing series count, instances in the window and whether the target exists/will be created; `创建并开始同步` → `op("rule.add", …)` then `op("trigger", {rule, wait: true})`, the new wire animates once.
- **Tests:** each control writes the expected `config.toml` change (read back through `GET /api/config` and the daemon's file) and survives a reload; validation error shown inline; pause makes the wire dashed and the calendar shows events as paused; new line: preview numbers, create, wire appears; delete keep-copies removes the wire; delete-with-copies shows the retiring state.
